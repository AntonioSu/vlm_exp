80GB 标尺 · 训练留一半给 rollout · 评测把整卡给 KV

权重

一个参数 fp16 / bf16 占 2 个字节。不跟 batch、seq 走。

权重 = 参数个数 × 2 字节

$$\text{2B:}\quad 2.27{\times}10^{9}\times 2\,\mathrm{B} = 4.24\,\mathrm{GiB}$$
$$\text{4B:}\quad 4.66{\times}10^{9}\times 2\,\mathrm{B} = 8.68\,\mathrm{GiB}\ \text{（含 vision）}$$

参数个数来自 safetensors 字节 $/2$。FSDP 按卡数切开：2B 两卡各约 2.1G，4B 四卡各约 2.2G。

梯度 / Adam

训练时另两份跟参数个数走的状态，不是权重本身。2B 卸到 CPU，4B 留在卡上。

梯度同样 × 2 字节；Adam 的 m、v 各 4 字节（fp32），合计 × 8 字节

$$\text{2B 梯度:}\quad 2.27{\times}10^{9}\times 2\,\mathrm{B} = 4.24\,\mathrm{GiB}$$
$$\text{2B Adam:}\quad 2.27{\times}10^{9}\times 8\,\mathrm{B} = 16.96\,\mathrm{GiB}\ \text{（卸到 CPU）}$$
$$\text{4B 梯度:}\quad 4.66{\times}10^{9}\times 2\,\mathrm{B} = 8.68\,\mathrm{GiB}$$
$$\text{4B Adam:}\quad 4.66{\times}10^{9}\times 8\,\mathrm{B} = 34.72\,\mathrm{GiB}\ \text{（4 卡，每卡 }8.68\,\mathrm{GiB}\text{）}$$

激活

跟 micro-batch $B$、序列长 $S$、隐层 $H$ 成正比。一步 256 条不进这条公式——反传 $B{=}1$。

batch 与 seq

$$N_{\mathrm{seq}} = B_{\mathrm{train}}\times n = 32\times 8 = 256$$
$$S = S_{\mathrm{prompt}}+S_{\mathrm{resp}} = 1024+16384 = 17408$$
$$B = B_{\mathrm{micro/gpu}} = 1$$

一层激活（bf16）

$$M_{\mathrm{res}} = B\,S\,H\cdot 2,\qquad M_{\mathrm{mlp}} = B\,S\,I\cdot 4$$

checkpoint 开 / 关

$$M_{\mathrm{act}}^{\mathrm{ckpt}} \approx M_{\mathrm{res}}+M_{\mathrm{mlp}},\qquad M_{\mathrm{act}}^{\mathrm{no}} \approx L\,(M_{\mathrm{res}}+M_{\mathrm{mlp}})$$

未分块的 logits（脚本已 chunk，峰值不走这条）

$$M_{\mathrm{logits}} = B\,S\,V\cdot 2$$

$I$ 为 MLP intermediate；$M_{\mathrm{mlp}}$ 的 $4{=}2$ 字节 $\times$ gate+up。 2B：$H{=}2048$，$I{=}6144$，$L{=}24$ → $M_{\mathrm{res}}{=}68$ MiB，$M_{\mathrm{mlp}}{=}408$ MiB；checkpoint 峰值约一层，不开则 $\times 24$。 4B：$H{=}2560$，$I{=}9216$，$L{=}32$ → $85$ MiB + $612$ MiB。 $V{=}248320$ 时 $M_{\mathrm{logits}}{=}8.05$ GiB，因此 entropy_from_logits_with_chunking=True。 MM 另加 ViT：$P{\approx}2304$ patch、$H_{\mathrm{vit}}{=}1024$，一层约 $P H_{\mathrm{vit}}\cdot 2 \approx 4.7$ MiB，相对 $S{=}17$K 可忽略；图 token 进 LLM 后算进 $S$。

KV

只计 full attention。跟并发条数和当前长度成正比，是训练时最大的一块。

每 token（K+V，bf16）

$$m = n_{\mathrm{full}}\cdot n_{\mathrm{kv}}\cdot d\cdot 2\cdot 2$$

一步打满 max seq

$$M_{\mathrm{KV}} = N_{\mathrm{seq}}\cdot S\cdot m$$

每卡（TP 或数据并行均分）

$$M_{\mathrm{KV}}^{\mathrm{gpu}} = \frac{M_{\mathrm{KV}}}{N_{\mathrm{gpu}}}$$

$n_{\mathrm{full}}$ = full attn 层数（interval=4）；$d{=}256$。GDN/linear 是常数量级 state，不进 $m$。 2B：$n_{\mathrm{full}}{=}6$，$n_{\mathrm{kv}}{=}2$ → $m{=}12$ KiB/token；$M_{\mathrm{KV}}{=}256\times 17408\times 12\,\mathrm{KiB}{=}51.0$ GiB；TP=1、2 卡 → 每卡 $25.5$ GiB。 4B：$n_{\mathrm{full}}{=}8$，$n_{\mathrm{kv}}{=}4$ → $m{=}32$ KiB/token；$M_{\mathrm{KV}}{=}136$ GiB；TP=4 → 每卡 $34.0$ GiB。 实际长度往往 < $S$，上式是上界；vLLM 再按空闲显存的 $0.5$ 申请一块 KV 池。

为什么 Easy-32K 能 pack、MM 不能

Geo 用不满 KV；MM 文本会把 KV 打满

1. Geo：长尾 decode，真正用到的 KV 不多

一批 128 条。即便 128 条都打到 17K，KV 也只有 \(128 \times 17408 \times 12\,\mathrm{KiB} \approx 25\,\mathrm{GiB}\)。 独占却申请了 57 GiB（按 263 条打满来的），多出来的是预留，不是正在用的。 长尾时短序列已经结束，活着的更少，瞬时 KV 更低。 GPU 23–25%：慢在等最长那几条 decode，不是 KV 容量。 所以把 util 砍到 0.42（约 27 GiB）对 Geo 几乎没影响——25 GiB 还是装得下这一批。

2. MM 文本：并发高，把 KV 打满了——砍了才疼

evalscope 会把很多请求堆进 vLLM（batch=10 只是 HTTP 侧，引擎里连续批处理）。 独占 KV 60.85 GiB ≈ 199 条，GPU 90–100%：并发已经把 KV 池用满，算力也打满。 0.42×2 之后每路只剩 ≈ 88 条，并发腰斩，MATH L3 15 min → 40 min。

3. 同一套 MATH n=8，为什么 Easy pack 快、MM pack 慢

题一样：MATH-500，n=8，max_tokens=16384。不是 MM 开了 CoT、Easy 没评 math。 差在 vLLM 怎么起。
