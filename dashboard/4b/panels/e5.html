E5 REINFORCE++ · 一页速览

E5 · REINFORCE++ —— evalscope aime25 step150 第三（57.5%），mmlu 与 E1 并列

不做组内 baseline，改为全 batch 白化折扣 return + mse 形式 KL loss。pass 末段与其它组同处 88–91% 带；offline 侧 aime25 末步表现突出。

  • 算法设定：REINFORCE++：全 batch 白化折扣 return；mse 形式 KL loss（与 E1 同为保留 KL 的两组）。
  • 学习信号：pass 末段 88–91%；mmlu_temp 三 checkpoint 都在 91.2–91.5% 窄带。
  • 稳定性：有 KL 约束；曲线整体平稳，无 E2 式梯度尖峰。
  • 耗时：均值 ~13.3 min/step（gen ≈48%，update_actor ≈32%，ref+old≈18%）；总墙钟约 33.3h。
  • 评测亮点：offline aime25@150=57.5%（第三）；aime24@150=77.08%；mmlu 与 E1 并列高位；三项全 step 已齐。

耗时拆解

单步墙钟 · gen / update_actor / ref / old_log_prob 等 stage

展开 stage 释义 · gen / update_actor / ref / adv …
  • gen (rollout)：vLLM 采样生成响应，通常占一半以上时间；随响应变长而抬升。
  • update_actor：FSDP 上策略网络反向与参数更新（PPO/GRPO clip 目标）。
  • ref：参考模型前向算 logprob，供 KL loss；关闭 KL 的组（如 DAPO / Dr.GRPO）此项为 null/≈0。
  • old_log_prob：用更新前策略再算一遍 logprob，供重要性采样 ratio。
  • update_weights：把新权重同步回 rollout engine（vLLM），一般数秒。
  • adv：advantage 计算阶段墙钟（含 reward 整理 + compute_advantage），不是 advantage 数值本身；通常 <1s。
  • reward：打分/奖励函数本身的计时；多数配置下几乎可忽略（≈0）。
