融合 Token

Vision Encoder

ViT

Vision Transformer

将图像切成固定大小的 patch，线性投影后加位置编码，再送入标准 Transformer encoder。输出 patch / CLS 特征序列，供下游分类、检测，或作为 VL 模型的视觉前端（如 Qwen-VL / LLaVA 一类栈）。相对 CNN：全局感受野更早、扩展性更好，但更吃数据与算力。

核心：image → patches → Transformer · 序列化视觉特征

优点

与 LLM 同构（注意力），易规模化；长程依赖与全局上下文强；预训练生态成熟（CLIP-ViT、SigLIP 等）。

缺点

小数据上不如 CNN 稳；高分辨率时 token 数平方级涨；局部归纳偏置弱，细粒度纹理有时吃亏。

Latent Model · Continuous

VAE

Variational Autoencoder

编码器把输入映到连续潜分布（常见对角高斯），从中采样再解码重建。训练目标 ≈ 重建损失 + KL（相对先验）。在多模态里常作图像压缩前端（如扩散模型的 latent）、或连续视觉表征瓶颈；与「直接 ViT 特征进 LLM」是另一条轴。

核心：encode → 采样 z ~ q(z|x) → decode · ELBO

优点

潜空间连续、可插值；压缩比高，利于生成与长图；概率建模清晰，易接下游扩散 / 控制。

缺点

重建易糊（尤其小 latent）；KL 塌缩 / 后验坍塌常见；连续 z 不如离散码直接当「视觉词」喂自回归 LLM。

Latent Model · Discrete

VQ-VAE

Vector Quantized VAE

在 VAE 思路上把连续 latent 量化到码本（codebook）：每个空间位置选最近码向量，得到离散 index 序列。解码器从码向量重建图像。这样图像变成「视觉词表」上的 token，可与文本一样做自回归（如早期 DALL·E / Parti 路线），或作多模态统一 tokenizer。

核心：连续 z → nearest code · 离散视觉 token

优点

离散 token 与 LLM 接口自然；码本可共享跨模态词表直觉；生成可控、易做 AR 建模。

缺点

码本塌缩 / 利用率不均；量化误差伤细节；训练需 commitment loss、EMA 等技巧，工程更烦。

Bridge · Vision → LLM

Projector

视觉–语言投影 / 适配器

ViT（或其它视觉编码器）输出维度通常不等于 LLM 词嵌入维。Projector（MLP / 线性层 / Q-Former / Perceiver Resampler 等）把视觉特征投到 LLM 输入空间，再与文本 token 拼进同一序列。LLaVA 式「冻 ViT + 训投影 + 指令微调」是常见低成本配方；也有端到端全开。

核心：视觉特征 → 对齐维数/语义 → LLM embedding

优点

改动面小、易插拔；可冻大视觉/语言骨干省算力；MLP 投影实现简单、收敛快。

缺点

浅投影表达力有限，细粒度接地弱；与冻结编码器耦合时，能力上限受前端束缚；Q-Former 等更强桥更重、更难训。

Pretrain · Cross-Modal

图文对齐

Contrastive / Matching / Captioning

让图像与文本落在共享语义空间。代表：CLIP / SigLIP 式对比学习（同图文对拉近、不同对推远）；还可加图文匹配、图文生成（caption）辅助。对齐好的 ViT 常直接当 VL 的视觉塔；本看板多模态训练则在已对齐底座上再做 GRPO 等后训练。

核心：对比 / 匹配 / 生成 · 跨模态共享语义

优点

零样本迁移强；为 VL 提供现成视觉塔；对比目标规模化效果好。

缺点

偏全局语义，细粒度定位/OCR 弱；负样本与 batch 规模敏感；与生成式目标（caption）需额外平衡。

Integration

模态融合

Early / Late / Cross-Attention

图像与文本如何进同一计算图：早期融合（视觉 token 与文本拼序列，自注意力混）；晚期融合（两塔分别编码再拼接/点积）；交叉注意力（语言 query 视觉 key/value，如 Flamingo）。现代开源 VL 多走「视觉 token 插入 LLM 序列」的早期/中期融合。

核心：拼序列 / 双塔 / 交叉注意 · 决定交互深度与成本

优点

拼序列实现简单、与 LLM 训练栈统一；交叉注意可省视觉 token、控算力；晚期融合推理轻、易部署。

缺点

拼序列让上下文暴涨；晚期融合交互浅，复杂推理弱；交叉注意结构异构，实现与并行更麻烦。

Efficiency · Resolution

视觉 Token

Patch 数 · 分辨率 · 压缩

高分辨率 → 更多 patch → 更长视觉前缀 → 训练/推理更贵。工程上常用：动态分辨率、any-res 切图、自适应池化、Perceiver 压缩、或 VAE/VQ 降到少而密的 token。多模态 RL（长 response + 图）时，视觉 token 预算往往是 OOM 与速度的第一瓶颈。

核心：精度 ↔ 长度权衡 · 决定显存与吞吐

优点

提高分辨率/token 数可明显抬 OCR、细粒度几何；压缩策略能把长图塞进固定上下文。

缺点

token 过多直接打爆上下文与 KV；过度压缩丢细节；动态分辨率让 batch 形状不齐，工程复杂。

典型流水线

理解型 VL（进 LLM）vs 生成型（潜空间）

  1. 1

    理解型：ViT → Projector → LLM

    图像经 ViT（常已 CLIP/SigLIP 对齐）编码，投影成视觉 token，与文本拼进 LLM。适合 VQA、文档、几何推理（如 Geo3K）与多模态 RL 后训练。

  2. 2

    生成型：VAE / VQ-VAE → 生成头

    像素压到 latent 或离散码，再扩散 / 自回归生成。与「图→文理解」栈不同，但共享「视觉要先进紧凑表征」这一层。

  3. 3

    和本看板的关系

    多模态训练页跑的是理解型栈 + GRPO；本页只讲视觉–语言构件，不改 RL 算法变量。底座语言侧见 基座。
